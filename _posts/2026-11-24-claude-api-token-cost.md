## API 요금은 결국 토큰 수입니다

ChatGPT나 Claude를 웹에서 쓸 때는 월 구독료만 내면 되지만, 서비스에 붙이려고 **API**로 부르면 사용한 만큼 요금이 나옵니다. 요금의 기준은 **토큰**입니다. 보내는 글(입력)과 받는 글(출력)을 토큰 단위로 세어, 100만 토큰당 정해진 가격을 곱합니다.

그러니 비용을 줄이는 방법도 단순합니다. 입력 토큰을 줄이고, 출력 토큰을 줄이고, 같은 입력을 반복해서 보낼 때는 싸게 처리되게 하는 것입니다. 이 글은 Claude API에서 이 세 가지를 실제로 호출해 토큰 수와 비용이 얼마나 달라지는지 측정한 결과를 정리했습니다.

<!--more-->

실험은 2026년 11월 24일 Claude Haiku 5.5 모델과 Anthropic Python SDK 2.13.0으로 했습니다. 모든 숫자는 API 응답의 `usage` 값을 그대로 옮긴 것입니다. 비용은 공식 요금표로 계산했고, 실험 전체에 든 비용은 약 **$0.004**였습니다. 같은 실험을 다시 돌려도 답변 내용과 출력 토큰 수는 조금씩 달라질 수 있습니다.

## 1. 먼저 요금 구조 이해하기

Claude API 요금은 입력과 출력 가격이 따로 있고, **출력이 입력보다 비쌉니다**. 실험에 쓴 Claude Haiku 5.5의 공식 요금(프롬프트 10만 토큰 이하 기준)은 다음과 같습니다.

| 항목 | 100만 토큰당 |
|---|---|
| 입력 | $0.10 |
| 출력 | $0.50 |
| 캐시 저장(5분) | $0.125 (입력의 1.25배) |
| 캐시 읽기 | $0.01 (입력의 0.1배) |

같은 회사 모델이라도 가격 차이가 큽니다. 예를 들어 Claude Opus 5.5는 입력 $4, 출력 $20입니다. 모델마다 가격과 캐시 읽기 배율이 다르니, 실제로 쓸 모델의 요금은 공식 요금표에서 확인하세요.

## 2. 무료로 미리 세기: 토큰 수 세기 API

요청을 보내기 전에 토큰이 몇 개인지 알고 싶다면 `count_tokens` API를 씁니다. 공식 문서에 따르면 **무료**이고, 분당 요청 수 제한만 있습니다. API 키는 필요합니다.

```python
import anthropic

client = anthropic.Anthropic()  # ANTHROPIC_API_KEY 환경 변수를 읽음
n = client.messages.count_tokens(
    model="claude-haiku-5-5",
    messages=[{"role": "user", "content": "세어 볼 문장"}],
).input_tokens
print(n)
```

같은 뜻의 한국어 문장과 영어 문장을 두 모델로 세어 봤습니다.

| 문장 | Claude Haiku 5.5 | Claude Haiku 4.5 |
|---|---|---|
| 한국어 (회의 안내 한 문장) | 68 | 68 |
| 영어 (같은 뜻) | 50 | 38 |

Claude 문서는 Claude 4.7 이후 모델의 새 토크나이저가 같은 글을 약 30% 더 많은 토큰으로 센다고 안내합니다. 실제로 영어 문장은 38에서 50으로 약 32% 늘었습니다. 이 한국어 문장은 두 모델에서 같게 나왔습니다. 문장 하나로 본 결과라 일반화할 수는 없지만, **모델을 바꿀 때는 토큰 수를 다시 세어 봐야 한다**는 점은 분명합니다.

## 3. 입력 줄이기: 인사말과 배경 설명을 덜어내기

메일 제목 하나를 부탁하는 같은 요청을 두 가지로 보냈습니다. 하나는 인사와 사정을 길게 붙인 프롬프트, 하나는 핵심만 남긴 프롬프트입니다.

```text
장황한 버전: 안녕하세요. 제가 지금 회사에서 일을 하고 있는데요, 혹시 괜찮으시다면
부탁을 하나 드려도 될까요? ... (중략) ... 정말 감사합니다.

핵심 버전: 팀장님께 보낼 메일 제목 1개만 써 줘. 내용: 다음 주 월 10시 신규
프로젝트 킥오프, 금요일까지 참석 여부 회신.
```

| 프롬프트 | 입력 토큰 | 출력 토큰 | 비용 |
|---|---|---|---|
| 장황한 버전 | 277 | 137 | $0.000096 |
| 핵심 버전 | 78 | 35 | $0.000025 |

입력이 72% 줄었고, 덩달아 답도 짧아졌습니다. 두 버전 모두 쓸 만한 제목을 돌려줬습니다. 한 번에는 아주 작은 돈이지만, 같은 프롬프트를 하루 수만 번 부르는 서비스라면 차이가 커집니다. 다만 배경 설명을 무조건 빼라는 뜻은 아닙니다. 답의 품질에 필요한 맥락은 남기고, **인사말이나 반복 설명처럼 결과에 영향이 없는 부분**만 덜어내는 것이 요령입니다.

## 4. 출력 줄이기: 길이 지시와 effort

출력 토큰은 입력보다 5배 비쌉니다(Haiku 5.5 기준). 그래서 출력 길이를 다루는 것이 더 효과적입니다. "REST API와 GraphQL의 차이를 설명해 줘"를 네 가지 방식으로 보냈습니다.

| 방식 | 출력 토큰 | 결과 |
|---|---|---|
| 아무 제한 없음 | 2,018 | 긴 설명 (약 2,300자) |
| "세 문장 이내로" 추가 | 247 | 세 문장 답 |
| 세 문장 + `effort: low` | 202 | 세 문장 답 |
| `max_tokens: 60`만 설정 | 60 | **답이 중간에 끊김** (`stop_reason: max_tokens`) |

"세 문장 이내로" 한마디로 출력 토큰이 약 88% 줄었습니다. 여기에 `effort`를 `low`로 낮추자 조금 더 줄었습니다.

### effort와 생각(thinking) 토큰

Claude Haiku 5.5는 요청에 `thinking`을 지정하지 않으면 답하기 전에 스스로 생각하는 **적응형 생각(adaptive thinking)**이 기본으로 켜져 있습니다. 이 생각에 쓴 토큰도 출력 토큰으로 계산되고 `max_tokens`에 포함됩니다. `output_config`의 `effort`를 낮추면 생각을 덜 하므로 출력 토큰이 줄어듭니다.

```python
client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=4000,
    output_config={"effort": "low"},
    messages=[{"role": "user", "content": "REST API와 GraphQL의 차이를 세 문장 이내로 설명해 줘."}],
)
```

분류나 짧은 답처럼 깊이 생각할 필요가 없는 일에는 `low`가 잘 맞습니다. 반대로 어려운 추론이나 코딩에서는 effort를 낮추면 품질이 떨어질 수 있으니, 실제 요청 몇 개로 품질을 확인한 뒤 정하세요.

### max_tokens는 "줄이는 도구"가 아니라 "안전장치"

`max_tokens: 60`은 출력을 60토큰에서 **잘라 버립니다**. 비용은 가장 적었지만 답이 중간에 끊겨 쓸 수 없었습니다. 생각 토큰까지 포함되므로, 너무 작게 잡으면 생각만 하다가 답을 하나도 못 받을 수도 있습니다. 길이는 프롬프트로 정하고, `max_tokens`는 예상보다 길게 폭주하는 경우를 막는 상한으로 넉넉하게 두는 편이 안전합니다.

## 5. 반복되는 입력은 캐싱: 가장 큰 절약

챗봇이나 사내 문서 도우미는 질문마다 **같은 긴 시스템 프롬프트**(규정, 매뉴얼, 지시문)를 함께 보냅니다. 이 부분을 **프롬프트 캐싱**으로 저장해 두면, 다음 요청부터는 캐시에서 싸게 읽습니다.

가상의 회사 '하늘상사' 사내 규정 20개 조항(약 3,400토큰)을 시스템 프롬프트로 넣고, 질문 5개를 캐싱 없이 한 번, 캐싱을 켜고 한 번 보냈습니다. 캐싱은 시스템 프롬프트 블록에 `cache_control` 한 줄을 붙이면 됩니다.

```python
system = [{
    "type": "text",
    "text": handbook,                       # 약 3,400토큰짜리 사내 규정
    "cache_control": {"type": "ephemeral"}, # 기본 5분 캐시
}]
r = client.messages.create(
    model="claude-haiku-5-5", max_tokens=1000,
    output_config={"effort": "low"},
    system=system,
    messages=[{"role": "user", "content": "연차는 어디서 신청해?"}],
)
print(r.usage.input_tokens,
      r.usage.cache_creation_input_tokens,
      r.usage.cache_read_input_tokens)
```

| 요청 | 캐싱 없음: 입력 | 캐싱: 일반 입력 | 캐싱: 캐시 저장 | 캐싱: 캐시 읽기 |
|---|---|---|---|---|
| 1번째 | 3,394 | 18 | 3,376 | 0 |
| 2번째 | 3,392 | 16 | 0 | 3,376 |
| 3번째 | 3,397 | 21 | 0 | 3,376 |
| 4번째 | 3,398 | 22 | 0 | 3,376 |
| 5번째 | 3,393 | 17 | 0 | 3,376 |

첫 요청은 규정 3,376토큰을 캐시에 **저장**했고, 두 번째부터는 같은 3,376토큰을 캐시에서 **읽었습니다**. 일반 입력으로 계산된 건 질문 부분 20토큰 안팎뿐입니다.

비용으로 바꾸면 다음과 같습니다(출력 포함).

| 구분 | 캐싱 없음 | 캐싱 |
|---|---|---|
| 1번째 요청 | $0.000376 | $0.000460 |
| 2~5번째 평균 | $0.000379 | $0.000075 |
| 5번 합계 | $0.001890 | $0.000760 |

첫 요청은 캐시 저장 요금(1.25배) 때문에 오히려 조금 더 비쌌습니다. 하지만 두 번째부터는 요청당 비용이 약 80% 줄었고, 다섯 번만 보내도 전체 비용이 60% 줄었습니다. 공식 문서도 5분 캐시는 **한 번만 다시 읽어도** 이득이라고 설명합니다.

### 캐싱이 안 되는 흔한 이유

- **앞부분이 매번 달라짐:** 캐시는 앞에서부터 글자 단위로 같아야 맞습니다. 시스템 프롬프트에 현재 시각이나 요청 ID를 넣으면 매번 캐시를 새로 만듭니다. 바뀌는 내용은 캐시할 부분 **뒤**에 두세요.
- **너무 짧음:** 모델마다 캐시할 수 있는 최소 길이가 있어서, 짧은 프롬프트는 표시를 붙여도 캐시되지 않습니다. 오류는 나지 않고 `cache_creation_input_tokens`가 0으로 나옵니다.
- **시간이 지남:** 기본 캐시는 5분 동안 유지됩니다. 요청 간격이 길면 1시간 캐시(저장 2배)를 고려할 수 있습니다.

그래서 캐싱을 켰다면 `cache_read_input_tokens`가 실제로 0보다 큰지 꼭 확인해야 합니다.

## 6. 급하지 않은 일은 Batch API

바로 답이 필요 없는 대량 작업(리뷰 수천 건 분류, 문서 일괄 요약 등)은 **Batch API**로 모아 보내면 입력과 출력 모두 **50% 할인**됩니다. 결과는 비동기로 나중에 받습니다. 캐싱 할인과 함께 적용할 수 있다고 공식 문서에 나와 있습니다. 이번 실험에서는 Batch API를 직접 측정하지 않았습니다.

## 7. 하루 1만 건이라면: 계산 예시

위 측정값으로 단순 계산해 보겠습니다. 사내 규정 도우미에 하루 1만 건의 질문이 들어오고, 캐시가 항상 유지된다고 가정한 **계산 예시**입니다.

| 구분 | 요청당 비용 | 하루 1만 건 |
|---|---|---|
| 캐싱 없음 | 약 $0.000379 | 약 $3.79 |
| 캐싱(캐시 읽기) | 약 $0.000075 | 약 $0.75 |

실제로는 트래픽이 끊기면 캐시가 만료돼 다시 저장 비용이 들고, 질문과 답의 길이도 다양하므로 이 숫자보다 높게 나옵니다. 더 비싼 모델을 쓰면 절대 금액 차이도 그만큼 커집니다.

## 8. 비용을 줄이기 전에 확인할 것

- **품질 먼저 확인:** 토큰을 줄인 프롬프트, 낮춘 effort, 더 싼 모델이 실제 요청에서도 충분한 답을 주는지 표본을 직접 읽어 보세요. 품질 비교 방법은 [LLM 평가에서 평균 점수가 속이는 것](/2026/11/24/llm-eval-average-score-trap/)에 정리해 두었습니다.
- **요청당이 아니라 일당 비용:** 싼 설정 때문에 재질문이나 재시도가 늘면 오히려 비싸질 수 있습니다.
- **API 키 관리:** 키는 코드에 직접 쓰지 말고 환경 변수로 두고, 저장소에 올리지 마세요.
- **회사 데이터:** 사내 자료를 API로 보내기 전에 회사 보안 규정과 계약 조건을 확인하세요.

## 마무리

- API 요금은 **토큰 수 × 단가**입니다. `count_tokens`로 미리 무료로 셀 수 있습니다.
- 인사말과 반복 설명을 덜어내자 입력이 **72%** 줄었습니다.
- "세 문장 이내로" 같은 길이 지시가 출력을 **88%** 줄였고, `effort: low`가 생각 토큰을 더 줄였습니다.
- `max_tokens`는 답을 잘라 버리니 상한으로만 넉넉하게 둡니다.
- 반복되는 긴 시스템 프롬프트는 **캐싱**으로 두 번째 요청부터 약 **80%** 아꼈습니다. `cache_read_input_tokens`로 꼭 확인하세요.

로컬 모델로 토큰 걱정 없이 실험해 보고 싶다면 [Ollama로 로컬 LLM 시작하기](/2026/11/24/ollama-local-llm-start/)도 참고해 보세요.
